# ProjectBrief — Arcane Vanguard（奥术先锋）

- 最后更新：2026-10-21
- 状态：M0 工程基线（进行中）

## 1. 一句话定位

面向个人开发与 UE/C++ 秋招作品集的**可玩第三人称魔法战斗 Demo**。

## 2. 三个必须同时满足的目标

| 目标 | 判定方式 |
|---|---|
| 可玩性 | 玩家能移动、瞄准、攻击、放技能、击败敌人、完成任务 |
| 技术展示 | C++ / 蓝图分工、GAS、角色与敌人框架、动画特效、UI、任务接口、工程化习惯 |
| 可解释性 | 项目负责人能讲清架构决策、数据流、类职责、测试结果与已知限制 |

## 3. V1.0 范围（做什么）

- 1 个可操作第三人称玩家角色、1 张小型战斗地图
- 1 种完整敌人（第 2 种为可选扩展）
- 普通攻击（Arcane Bolt）+ Q 奥术震荡 + E 霜缚 + R 星陨
- 生命值 / 法力值 / 冷却 / 伤害 / 控制 / 死亡流程
- 敌人基础感知、追击、攻击、死亡
- HUD：生命、法力、技能状态、任务进度
- 1 项可完成任务（击杀 3 名奥术守卫为必需目标）
- 关键战斗反馈（动画 / 特效 / 音效的最低可用组合）
- 可重复的测试清单、架构说明、运行说明、已知问题、演示视频

## 4. 明确不做（V1.0）

联机与服务器权威同步、开放世界与剧情过场、多英雄/装备/天赋/掉落经济、完整存档、复杂行为树与多阵营战术、自研 GAS 替代框架、为"架构完整"而过度泛化的插件体系、未经验证的整体旧项目迁移、以大量采购素材替代核心体验。

## 5. 质量优先级（冲突时从上往下取舍）

1. 正确性与稳定性
2. 核心战斗闭环
3. 架构可解释性与可维护性
4. 可读的视觉与音效反馈
5. 次要功能与内容数量
6. 非必要的复杂优化

## 6. 验收指标（10 条）

见 `GameDesign_V1.0.md` §2.2。摘要：工程可编译可运行、输入稳定、GAS 属性与效果符合设计、死亡只结算一次、任务进度不重复计数、UI 与实际状态一致、关键功能有测试证据、无阻断性崩溃、资产许可有记录、负责人能讲清实现。
