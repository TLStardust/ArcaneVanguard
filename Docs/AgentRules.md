# AgentRules — Agent 行为规范（本项目强制）

- 来源：`Docs/GameDesign_V1.0.md` §6
- 适用对象：主 Agent、执行 Agent（含子代理）
- 违反本文件的产出视为无效交付

## 1. 十条最高优先级规则

1. 先读项目文档、当前状态与相关代码，再行动。
2. 不把推测当作事实；无法验证时明确标注"未验证"。
3. 不在未扫描的情况下重构整个工程。
4. 不删除、覆盖或批量重命名资产，除非任务明确授权且已有备份或可回滚提交。
5. 不修改与当前任务无关的文件。
6. 不自行引入新插件、第三方依赖或大型资源包。
7. 不将编译成功等同于功能正确。
8. 不将静态检查、代码阅读或编辑器截图冒充真实运行测试。
9. 不伪造测试结果、日志、文件路径、类名或资产引用。
10. 不在没有用户确认的情况下扩展项目范围。
11. 发现已有实现时优先复用；修改前说明为什么原实现不足。
12. 每次任务结束必须更新状态记录，并列出未完成项。

## 2. 权限等级

| 等级 | 内容 | 前置条件 |
|---|---|---|
| L0 只读 | 扫描文件、读代码、读日志、列风险 | 通常不需要 |
| L1 局部修改 | 单一功能的小范围代码或文档改动 | 任务目标已确认 |
| L2 工程配置 | 模块依赖、插件启用、输入配置、关键资产引用 | **必须先说明影响**，重要变更需确认 |
| L3 结构性变更 | 大规模重构、批量迁移、删除资产、替换框架 | **必须明确批准**并准备回滚 |
| L4 不可逆/外部 | 发布、上传、购买、签署许可、删除唯一副本 | **不允许 Agent 自行执行** |

## 3. 标准任务流程（A→E）

- **A 读取与检查**：读 ProjectBrief / DevelopmentStatus / 相关模块；检查 UE 版本、插件、目标代码；搜索类与调用链；确认当前能否编译。
- **B 提出实施计划**：目标、现状与证据、预计改动文件、不修改范围、方案与替代、风险与回滚、验收条件、需确认事项。
- **C 执行最小改动**：一次一个可验收单元；先最小正确版本；保持 diff 小；不用脚本批量改写未检查的文件；改 `.uproject`/`.uplugin`/`Build.cs`/`Target.cs`/资产重定向必须说明影响。
- **D 验证**：按改动类型选择静态审查 / 编译 / 编辑器打开 / PIE / 自动化 / 手动清单 / 日志检查。每项必须记录"通过 / 失败 / 未执行 / 无法执行"并附证据。**未执行不得写通过**。
- **E 汇报与交接**：目标、改动清单、核心决策、验证命令与结果、已知问题与风险、回滚方式、更新后的状态、下一项建议任务。

## 4. 重大变更（需先批准）

更换 UE 小版本或升级工程、更换 GAS 架构、替换任务插件或改其公共接口、改变 ASC 所有权与初始化策略、批量改资产路径或重命名、新增需许可或付费的资源、引入联机/存档/装备等新系统、调整核心范围或验收指标。

记录要求：原因、影响范围、备选方案、迁移步骤、测试计划、回滚方式、批准结果（写入 `DecisionLog.md`）。
