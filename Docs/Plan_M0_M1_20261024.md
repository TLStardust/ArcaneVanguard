## 三、M1：角色框架与输入

### 3.1 策划案定义的目标与验收

**目标**：在不破坏模板行为的前提下，建立项目自己的角色扩展点。

**验收（四条，全部要满足）**：
1. 角色移动、镜头和跳跃仍正常
2. **输入无重复绑定**
3. 工程可编译
4. 新增类的职责与继承关系**有文档说明**

### 3.2 五个关键决策（需你拍板，我给建议）

| # | 决策 | 我的建议 | 理由 |

## 四、风险与约束

| 风险 | 影响 | 对策 |
|---|---|---|
| **BP 里残留失效的武器属性** | 建新角色类时可能带垃圾数据，或迁移时出错 | M1 开始前先确认 BP 是否要重建（见下） |
| **无 Git，改动不可回滚** | 每步都可能踩坏 | 每次改动前 `.bak-<时间戳>`；一步一验收 |
| **M0 的"基线提交"豁免** | 严格意义上 M0 不算 100% 通过 | 在 `DevelopmentStatus` 明确标注"经负责人豁免"，不粉饰 |
| **模板的输入绑定本身可能重复** | 如果模板就有 bug，M1 验收项会失败 | AV-031 先测基线（改之前先跑 5 次），再改，改完对比 |
| **UI/死亡/暂停时的输入行为** | 策划案 §4.4 要求明确 | M1 不实现，但 ADR-010 要写清"留到 M6 处理" |

### 待确认：`BP_ThirdPersonCharacter` 要不要重建？

现在这个 BP 里塞着一堆失效的武器属性（`WeaponMesh` 组件记录、`WeaponHiddenAnimNames` 等），UE 加载时静默丢弃，不影响运行，但**不干净**。

| 选项 | 代价 | 结果 |
|---|---|---|
| **A. 不重建**（建议） | 0 | 能用，但 BP 里留着垃圾数据；以后可能困惑 |
| B. 重建一个新 BP | 需重新配网格/AnimBP/输入资产 | 干净，但要重配一遍（约 10 分钟） |
| C. 在编辑器里手动清 | 需逐个删失效属性 | 中等，但容易漏 |

**我建议 A**：M1 不动 BP，等 M3 需要挂武器时再顺手清理。
